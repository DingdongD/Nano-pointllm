# PointLLM analytical architecture estimator

This directory records a corrected exploratory GTSU architecture estimate for the
PointLLM-7B workload `B1/S768/O128`. It is generated by
[`architecture_simulator/`](../../../architecture_simulator/README.md).

## Scope and fidelity

- Model: uncalibrated operation-level analytical cycles and traffic at 1 GHz.
- Baseline: 32x32 tensor fabric, Split-K 32, 256 geometry lanes, 819.2 GB/s
  HBM with 80% efficiency, 32 MiB SRAM, and 256 weight-unpack B/cycle.
- Search: 320 unique designs spanning tensor shape, Split-K, geometry lanes,
  HBM, SRAM, and 128/256/512/1024 weight-unpack B/cycle.
- Accuracy policy: W8 throughout. W4 is supported as a study knob but is not
  assumed accuracy-safe by this architecture report.
- Energy and area: intentionally `null` until RTL synthesis and
  PTPX/CACTI-backed characterization are supplied.
- Event-level cycle model, C-model, RTL, bank conflicts, DRAM timing, and RTL
  correlation: **not implemented**.
- Machine-readable status: `exploratory_only`, `event_level_model=false`,
  `rtl_correlated=false`, `publishable_performance_claim=false`.

## Correction notice

The original report in commit `a5650f7` is superseded. It serialized decoder
attention across 32 heads and omitted PointBERT bridge/position/vector stages.
That inflated decode-attention cycles by about 74x over the configured tensor
peak lower bound. The old `7082.26 ms`, `1.406x`, and attention breakdown must
not be cited. This revision parallelizes head/query rows, adds the omitted
stages, fixes KNN HBM accounting and sub-byte packing, and passes 374 model
shape and analytical-conservation checks.

## Main observations

The corrected equations estimate 6205.75 ms end-to-end and 20.63 output
tokens/s for the baseline. Decode is 3460.21 ms (55.76%); prefill is 2724.92 ms
(43.91%). Within decode, 96.96% of estimated operation cycles are assigned to
unpack-bound operators, 2.90% to HBM-bound operators, and 0.14% to
compute-bound operators. Prefill remains compute-bound under these equations.

The minimum-latency searched point uses a 32x32 tensor fabric, Split-K 16, 256
geometry lanes, 819.2 GB/s HBM, 16 MiB SRAM, and 1024 unpack B/cycle. It predicts
4161.77 ms end-to-end, 1416.54 ms decode, and 30.76 output tokens/s. Relative
to the same analytical baseline this is a 1.491x end-to-end and 2.443x decode
trend. At this point, 99.66% of estimated decode operation cycles are assigned
to HBM-bound operators.

These ratios are equation sensitivity, not measured or cycle-simulated ASIC
speedups. They cannot support a hardware performance claim. The current Pareto
set treats unpack throughput as monotonic resource demand but cannot translate
it to mm2 or pJ before characterization.

## Design implication

The first RTL candidates should be a parameterized W8 unpack/scale pipeline and
one Split-K GEMV path, followed by a persistent FPS engine. The required
correlation sequence is analytical traffic -> event C-model -> RTL trace ->
synthesis/PTPX. A shared-versus-disaggregated architecture claim remains gated
on equal-area and equal-HBM characterization.

## Files

- `baseline_summary.csv`: compact baseline phase and bottleneck summary.
- `baseline_simulation.png`: phase latency, traffic, and top operations.
- `unpack_hbm_sensitivity.csv`: fixed-architecture transition from unpack to HBM.
- `pareto.csv`: 39 non-dominated designs under modeled resource axes.
- `sweep.png`: tensor, HBM, and unpack sensitivity.
- `ncu_evidence.json`: normalized GPU measurements used only as workload and
  bottleneck references, not ASIC cycle calibration.
- `validation.json`: 374 config/YAML/safetensors-shape and conservation checks,
  plus the explicit incomplete-fidelity matrix.

## Reproduce

```bash
cd /home/nano-pointllm/architecture_simulator
/opt/conda/envs/pointllm/bin/python -m pointllm_archsim preset \
  --batch_size 1 --input_tokens 768 --output_tokens 128 \
  --output workloads/pointllm_7b_b1_s768_o128.json
/opt/conda/envs/pointllm/bin/python -m pointllm_archsim simulate \
  --config configs/gtsu_baseline.json \
  --workload workloads/pointllm_7b_b1_s768_o128.json \
  --output_dir ../results/architecture_simulator/baseline_b1_s768_o128 --plot
/opt/conda/envs/pointllm/bin/python -m pointllm_archsim sweep \
  --config configs/gtsu_baseline.json --sweep configs/sweep_quick.json \
  --workload workloads/pointllm_7b_b1_s768_o128.json \
  --output_dir ../results/architecture_simulator/sweep_quick_b1_s768_o128 --plot
/opt/conda/envs/pointllm/bin/python -m pointllm_archsim validate \
  --config configs/gtsu_baseline.json \
  --workload workloads/pointllm_7b_b1_s768_o128.json \
  --checkpoint_config /mnt/llm_data/pointllm_ckpt/PointLLM_7B_v1.2_safetensors/config.json \
  --pointbert_config /home/PointLLM/pointllm/model/pointbert/PointTransformer_8192point_2layer.yaml \
  --output ../results/architecture_simulator/validation.json
```
